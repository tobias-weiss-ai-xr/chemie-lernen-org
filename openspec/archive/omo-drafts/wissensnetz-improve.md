## Decisions (with rationale)

1. **D3 ego graph → inline local module**: Replace CDN load with a small bundled d3-force-only build to eliminate network dependency and latency. The wissennetz full graph page keeps CDN for feature completeness.
2. **Entity detail SSR via Hugo data files**: Add entity JSON to `data/wissensnetz/` during the generate step. The Hugo template reads it server-side for name, category, articles, relations. JS only for the ego graph.
3. **Sequential execution order**: C4 → C2 → C1 → C3 → C6 → C5 (foundation first: fix data issues and performance before visual changes, SSR last since it touches build pipeline).
4. **No virtual scrolling**: Current 24-per-page pagination is adequate for ~500 entities. Virtual scrolling would add complexity without proportional benefit.
